# Отчет по лабораторной работе № 3: Реализация компонента AI-системы

**Выполнили:** Гуль Эмиль, Галиакберов Динар, ЕТ-312  
**Тема проекта:** AI-система предиктивного обслуживания оборудования (Predictive Maintenance)  
**Реализованный компонент:** Модуль локального инференса и бизнес-правил (`app/services/prediction.py`)

## 1. Входной и выходной контракт
Компонент принимает валидированный JSON-пакет (`PredictRequest`) со скользящим окном телеметрии (4 канала по 60 точек) и возвращает типизированный класс состояния (`PredictResponse`).

## 2. Алгоритм и прикладные правила
*   **Интеллектуальная функция:** Прямой прогон признаков через кастомную полносвязную нейросеть (двухслойный перцептрон на базе NumPy) с вычислением распределения вероятностей трех независимых классов (`safe`, `warning`, `critical`) через функцию Softmax.
*   **Прикладное бизнес-правило:** Если максимальная уверенность классификации ниже `0.75`, автоматически активируется fallback-режим, принудительно выставляющий класс с наивысшим фактором риска (`critical`).

## 3. Инструкция по запуску и тестам
1. Установка окружения: `python3 -m venv .venv && source .venv/bin/activate`
2. Установка зависимостей: `pip install -r requirements.txt`
3. Очистка кэша: `find . -type d -name "__pycache__" -exec rm -r {} +`
4. Запуск тестов: `python3 -m pytest -v`

## 5. Вывод
В лабораторной работе № 3 для проекта «AI-система предиктивного обслуживания» реализован компонент локального инференса. Он принимает временные окна телеметрии и возвращает класс риска с оценкой уверенности. Интеллектуальная функция реализована с помощью кастомных тензорных операций и функции Softmax; прикладные правила выполняются в модуле `prediction.py`. На тестовых входах продемонстрированы штатный режим, детекция аномалий и обработка ошибки валидации длины серии данных. Компонент полностью соответствует архитектуре ЛР № 2. Для дальнейшей интеграции необходимо упаковать компонент в Docker-контейнер и развернуть полноценный REST API на FastAPI. Цель работы достигнута.
